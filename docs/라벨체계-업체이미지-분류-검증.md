## 파이프라인에 꼭 넣을 것

**모든 사진에 모든 축을 시도하면 안 된다.** 샷 타입을 먼저 나누고 축을 제한해야 한다.

```
① 샷 타입 분류   → 클로즈업 / 반신 / 전신 / 공간 / 텍스트카드
② 사진 종류 게이팅 → 제품컷 / 부대시설 / 이벤트 / 비제품
③ 포즈·각도 감지  → 기립 여부, 정면/측면/후면
④ 축별 시도 여부 결정 → 판정 불가면 abstain
```

근거가 된 실제 사례:

- **얼굴 클로즈업은 메이크업에 최적이지만 헤어 정보는 0에 가깝다.** 게이팅 없이는 클로즈업에 헤어 라벨을 억지로 붙이는 오류가 대량 발생
- **좌식·기댄 포즈는 실루엣 축을 통째로 무효화한다.** 기립 여부를 먼저 보고 라인·트레인은 시도조차 하지 말 것
- **'생머리'는 부재의 증명이라 정면 컷으로는 원리적으로 확인 불가능하다** (뒤에서 묶었는지 알 수 없음)
- **통창은 '유리면 검출'이 아니라 '유리 너머 실외 객체 검출'로 구현해야 한다.** 면적만 보면 커튼 친 창을 전부 통창으로 오탐한다

**촬영 조건 편향도 주의.** `abybom` 10장은 전부 하이키 조명이라 **어떤 베이스든 광이 떠서 피부 축이 물광 하나로 붕괴**했다. 피부 라벨은 조명 조건과 함께 기록해야 한다.

## 이미지 소스 — API가 4분의 1을 해결한다

148장 중 **36장(24%)이 인스타 스크린샷**이었고 전부 `.png`였다. 캐러셀 점·화살표·프로필 아이콘이 찍혀 있다.

> `ccomostudio/image (4).png` — 프로필 아이콘과 캐러셀 점이 **'계란후라이' 판정의 핵심인 치마 퍼짐 하단부를 가렸다**

**Instagram API로 전환하면 이건 통째로 사라진다.** `media_url`은 UI 없는 원본을 주고, 캐러셀은 `children`으로 개별 이미지를 받으므로 인디케이터 자체가 없다. → **지금 이걸 고치려고 이미지를 재수집하지 말 것.**

API로도 안 없어지는 것: 업체 워터마크(`A BY BOM` 10/10장, `ccomo STUDIO`, `HINAF`), 저작권 URL 오버레이(ccomo 4장, **프레임 하단 15~20%가 판정 불가**), 촬영 조건 편향.

- `채플 컨벤션 웨딩홀 1.png` — 창밖 풍경이 실은 **벽화·세트**
- `야외.png` = `야외 스냅.png` **md5 완전 동일** → 삭제
